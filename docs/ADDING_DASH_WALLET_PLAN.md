# Adding native DASH wallet support (KISS plan)

Goal: Dash wallet with **create/restore, sync, receive, send** (mainnet, P2PKH only).
Buy/Sell intentionally out of scope. This is the plan; nothing is implemented yet.

## Approach (one line)

Copy the **dogecoin template** — the freshest Bitcoin-fork integration in the repo
(`cw_dogecoin` package + `lib/dogecoin/` part file + `--dogecoin` flag), with the Dash
values. Dash is *low like Dogecoin*: base58 P2PKH only, no segwit, no MWEB, BIP39 seeds.

## Order of work / verification (matches requested phasing)

1. **Wallet support** (A + B + C + D + di.dart + settings/prefs from E): configure with `--dash`, create wallet → address is a valid `X…` P2PKH (check base58 decode vs 0x4c prefix), sync from the chosen server, balance shows. Restore a known Dash seed → first address matches a reference BIP44 `m/44'/5'/0'/0/0` address.
2. **Receive**: address page, QR, `dash:` URI, address rotation/label new address.
3. **Send**: send a small amount to an external Dash address; verify fee rate ≈ electrum `estimatefee`, tx visible on Blockchair, change returns, no RBF; send-all flow; fee-priority selector works.
4. Run `flutter test test/core/address_validator_test.dart`, analyzer, and the repo lint before done.

## Deliberately skipped (add later if needed)

- InstantSend/masternode/ProTx special inputs (never handed to an ElectrumX scripthash wallet; regular P2PKH flows are unaffected)
- Hardware wallets, lightning, MWEB, payjoin, silent payments, WIF restore, testnet, RBF, custom fee slider, deep-link manifests, integration tests

## Risk notes

- Public Dash ElectrumX servers are scarcer than BTC's — validate the yml entries first; auto-switch + node settings absorb bad servers.
- Fee estimate `180/34+10` is doge's conservative legacy formula (doge margin ~20% high); fine for fee *estimates*, actual fees come from `estimatefee` rates.
- `WalletType` serialization is append-only in both Hive and `serializeToInt`, so no stored wallet can shift types.
